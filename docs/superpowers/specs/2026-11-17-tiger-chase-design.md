## 1. 기획 요약 (브리프)

| 항목 | 내용 |
|---|---|
| 목적 | **Three.js만으로 3D 애니메이션 영상을 어디까지 근사하게 만들 수 있는지 테스트**. 힉스필드로 넘어가기 전 비교 자료 |
| 진행 순서 | 1차 **A안(2.5D, 원본 이미지 활용)** → 2차 **B2안(코드로 만든 3D 모델)**. 두 결과를 나란히 비교 |
| 제외 | B1안(AI 3D 모델 생성). 이 역할은 힉스필드가 대신함 |
| 장면 | 가을 노을 산길에서 호랑이가 바구니 든 한복 할머니를 쫓음 |
| 톤 | 코믹한 추격전 *(제안 → 확정)* |
| 길이 / 규격 | 10.0초 (오디오에 따라 ±1초) / 1280×720(최종 렌더, 사용자 변경), 16:9, 30fps |
| 대사 | 호랑이만 대사, 할머니는 비명 |
| 엔딩 | 클리프행어 (정지 → 탈색 → 암전) |

### 목표
- 첨부 이미지의 룩을 최대한 유지하면서 3D 공간감(패럴랙스, 카메라 이동, 대기 효과)을 낸다.
- 제작 과정 자체를 측정해 B2안과 비교할 수 있게 남긴다. 측정 항목은 렌더 시간, 작업 단계 수, 한계점이다.

### 비목표
- 실제 3D 모델과 리깅 (B2안에서 진행)
- 립싱크 (A안에서는 포즈 이미지가 고정이라 불가능함. 한계로 기록)

### 실패 기준 (기술적으로 돌아가도 실패로 보는 것)
- API 키가 Git, 파일, 채팅 어디에든 남는 것
- 누끼 테두리가 번쩍이거나 할로가 생겨 판처럼 보이는 것
- 발이 땅에서 미끄러져 보이는 것
- 렌더할 때마다 결과가 달라지는 것 (비결정성)

## 3. 도구와 파이프라인

```
[에셋 전처리]  rembg(isnet) 누끼 → 조각 제거 → 테두리 정리(defringe)
              Depth-Anything(ONNX) 배경 깊이맵 → 전경 차폐 레이어 분리
[오디오]       Gemini TTS(호랑이 대사·할머니 비명) + Lyria(BGM) + 효과음
              → 길이 측정 → 타이밍 시트 확정
[애니메이션]   HyperFrames 프로젝트 안의 Three.js 캔버스
              GSAP 타임라인 = 모든 움직임의 유일한 시계 (hf-seek로 프레임별 렌더)
[검수]         HyperFrames check / snapshot, 저해상도 미리보기 MP4
[믹싱]         ffmpeg (딜레이 배치, 대사 구간 BGM 더킹, -14 LUFS / -1 dBTP)
[최종 렌더]    HyperFrames render 1080p30 → ffmpeg로 오디오 합본
```

| 도구 | 역할 | 확인 결과 (이 환경) |
|---|---|---|
| three.js 0.187 | 3D 장면, 포스트프로세싱 | npm 설치 가능 |
| gsap 3.15 | 타임라인, 이징 | npm 설치 가능 |
| hyperframes 0.9.61 | 결정적 프레임 렌더. Three.js는 `hf-seek` 이벤트로 공식 지원 | npm 설치 가능, 문서 확인함 |
| ffmpeg 6.1 | 효과음 합성, 믹싱, 인코딩 | 설치되어 있음 |
| rembg + isnet-general-use | 캐릭터 누끼 | **테스트 완료** (`cutout_test.jpg`) |
| Depth-Anything ONNX | 배경 깊이맵 | GitHub 접근 가능. Hugging Face는 막혀 있어 GitHub 릴리스로 받음 |
| Gemini API (TTS, Lyria) | 대사, BGM | 호스트 접근 가능, 키 필요 |

- **GPU 없음.** Chromium이 소프트웨어(SwiftShader)로 WebGL을 그린다. 프레임당 수백 ms에서 수 초가 예상되며, 300프레임이면 수 분 수준이다. 실제 측정값은 평가 기록에 남긴다.
- HyperFrames의 내장 `remove-background`는 사람 전용 모델(u2net_human_seg)이라 호랑이에는 쓰지 않는다. 그래서 rembg를 사용한다. *(내 판단)*

### API 키 처리 방식
1. 오디오 단계를 시작할 때 `request_credential` 보안 폼을 띄운다.
   - 대상 호스트: `generativelanguage.googleapis.com`
   - 헤더: `x-goog-api-key`
2. 키는 이 클라우드 환경의 네트워크 시크릿으로 저장되고, 프록시가 해당 호스트로 가는 요청에만 붙인다. 따라서 Claude는 키 값을 보지 못하고 파일에도 쓰지 않는다. 스크립트는 더미 값을 보내고, 프록시가 실제 키로 바꿔 넣는다.
3. `.gitignore`에 `.env*`, `*.key`를 추가한다. 커밋하기 전에 키 패턴(`AIza…`)을 검사한다.
4. 작업이 끝나면 환경 설정에서 시크릿을 삭제하도록 안내한다.

## 6. 장면 구성 (Three.js)

### 6.1 배경
- 원본 배경(1672×941)을 2배 업스케일하고 Depth-Anything으로 깊이맵을 만든다.
- **잘게 나눈 평면 메시**에 깊이맵으로 정점을 밀어내 실제로 입체감 있는 패럴랙스를 만든다. 카메라 이동은 작게 제한해서 늘어짐을 막는다.
- **전경 차폐 레이어:** 왼쪽 소나무 줄기, 열매 덤불, 아래쪽 바위를 깊이 임계값으로 잘라 별도 카드로 앞에 둔다. 호랑이가 나무 뒤에서 나오는 장면에 쓴다.
- **대기 효과:** 원경과 중경 사이에 안개 카드 2장(천천히 흐름), 상단에 따뜻한 빛줄기 카드(가산 합성)를 둔다.
- **대안:** 깊이맵 품질이 나쁘면 깊이 메시를 버리고 하늘·원경 / 중경 / 길 / 전경 4장의 카드 레이어로 바꾼다. *(내 판단)*

### 6.2 캐릭터 (누끼 카드)
- 포즈 시트를 3×2로 잘라 누끼를 따고, 가장 큰 덩어리만 남긴 뒤 테두리를 1~2px 줄이고 색을 정리한다.
- 사용 포즈:

| 캐릭터 | 포즈 | 용도 |
|---|---|---|
| 할머니 | g_2, g_3 | 달리기 교차 |
| 할머니 | g_4 | 뒤돌아보기 |
| 할머니 | g_5 | 앞으로 고꾸라지는 동작 (예비) |
| 호랑이 | t_2 | 웅크림 |
| 호랑이 | t_3, t_4 | 달리기 교차 |
| 호랑이 | t_5 | 덮치기 |
| 호랑이 | t_6 | 포효 (예비) |

- **달리기 표현:**
  - 포즈를 1초에 8~10번 교차한다 (애니메이션의 "투스" 방식).
  - 몸을 위아래로 흔들고(sin), 착지 순간 찌그러뜨렸다(squash) 공중에서 늘린다(stretch).
  - 몸을 약간 기울이고, 직전 포즈를 반투명 잔상 2장으로 남겨 모션 블러처럼 보이게 한다.
- **땅과의 접촉:** 발 아래에 흐린 타원 그림자를 둔다. 착지할 때 진해진다. 먼지 퍼프도 착지 프레임에서만 터뜨린다.
- **호랑이 말하는 입:** 대사 구간에서 입 벌린 포즈(t_3/t_4)와 입 다문 포즈(t_2)를 오디오 음량에 맞춰 바꾼다. 립싱크가 아닌 입 뻐끔거림 수준이며, 한계로 기록한다.
- 머티리얼은 원본 색을 살리는 Basic(조명 영향 없음)으로 하고, 장면 색감은 포스트 그레이드로 통일한다.

### 6.3 카메라와 컷
- 하나의 연속된 3D 장면 안에서 샷마다 카메라 위치를 바꾸는 방식으로 컷을 표현한다.
- 흔들림은 시드 고정 노이즈를 쓴다. 시간 t에만 의존해야 하므로 `Math.random`은 쓰지 않는다.
- 캐릭터는 항상 정면 또는 3/4 각도로만 보이게 한다. 카드라서 옆에서 보면 들통나기 때문이다.

### 6.4 포스트프로세싱
- 따뜻한 노을 그레이드, 비네트, 약한 필름 그레인(프레임 번호로 시드), 밝은 부분에만 약한 블룸
- S5 정지: 9.3초 이후에는 모든 움직임을 9.3초 상태로 고정하고 채도 0.35, 비네트를 강화한 뒤 9.7초부터 암전한다.

### 6.5 결정성 규칙 (HyperFrames 계약)
- 모든 상태는 시간 t에만 의존한다. GSAP 타임라인은 멈춰둔 채 `hf-seek`에서 `tl.seek(t)`를 호출하고, 그 다음 `renderer.render`를 한다.
- `requestAnimationFrame`, `Date.now`, 시드 없는 랜덤은 쓰지 않는다. 텍스처 로딩과 셰이더 컴파일은 `window.__hf.buildReady` 프로미스로 기다린다.
- 같은 시간을 두 번 스냅샷해서 결과가 바이트 단위로 같은지 확인한다.

## 9. 빌더에게 맡기는 것 / 위험 요소

- **모델 ID:** "Gemini Flash 3.8 TTS"와 "Lyria 3.5"의 정확한 ID는 키를 받은 뒤 모델 목록 API로 확인한다. Lyria를 이 키로 쓸 수 없으면 사용자에게 묻는다.
- **깊이맵 품질:** 불량하면 6.1의 4장 카드 대안으로 간다.
- **렌더 시간:** 소프트웨어 WebGL이 너무 느리면 해상도 그대로 두고 블룸이나 잔상 수를 줄인다.
- **누끼 품질:** 털 테두리 할로가 보이면 rembg 알파 매팅 옵션을 켜거나 birefnet 모델로 바꾼다.
