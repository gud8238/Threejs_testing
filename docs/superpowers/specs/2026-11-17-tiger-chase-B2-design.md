- 작성일: 2026-11-17
- 상태: 승인 대기
- 선행 결과: `docs/evaluation-A.md`, `renders/tiger_chase_A_720p.mp4`

## 1. 목적

A안 리포트의 결론은 "A안의 실패는 Three.js가 아니라 2D 에셋에서 왔다"였다. B2안은 **에셋 없이 Three.js 코드만으로** 같은 장면을 만들어, 이번에는 Three.js 자체의 3D 캐릭터·환경 표현력을 측정한다.

| 항목 | 내용 |
|---|---|
| 장면 | A안과 같은 스토리 비트 (S1~S5, 10초, 9.3초 정지 → 9.7초 암전) |
| 규격 | 1280×720, 30fps, 무음 |
| 산출물 | `renders/tiger_chase_B2_720p.mp4`, A/B2 비교 영상, `docs/evaluation-B2.md` |

### 목표 — A안의 실패 항목을 B2가 해결하는지 측정
| A안 실패 | B2에서 확인할 것 |
|---|---|
| F1 달리기 사이클 | 연속적인 절차적 보행. 지지 구간에서 발이 미끄러지지 않음 |
| F2 포즈 팝 | 모든 상태 전환을 가중치 블렌딩으로 처리 |
| F3 지면 접촉 | 실제 3D 지형 위에 발 고정, 그림자를 받는 지면 |
| F5 조명 통합 | 캐릭터가 장면의 태양광과 그림자를 받음 |
| F6 카메라 각도 | 자유 카메라. 최소 한 샷은 캐릭터 주위를 도는 오비트 |
| F8 표정과 입 | 눈썹·눈꺼풀·턱을 파라미터로 연기. 호랑이 대사 입, 할머니 비명 입 |

### 비목표
- 외부 3D 모델, 이미지 텍스처, AI 생성 에셋. **모든 형상과 텍스처는 코드(지오메트리 + 절차적 캔버스 텍스처 + 셰이더)로 만든다.**
- 첨부 이미지는 색을 고르고 형태를 참고하는 용도로만 본다.
- 오디오

### 실패 기준
- 렌더할 때마다 결과가 달라짐 (A안과 같은 결정성 테스트 적용)
- 지지 구간에서 발이 미끄러짐 (자동 테스트로 측정)
- 상태 전환에서 한 프레임에 관절이 튐 (자동 테스트로 측정)
- 소프트웨어 렌더 기준 프레임당 3초 초과 (300프레임이 15분 초과)

## 2. 접근 방식 (결정 완료)

| 안 | 내용 | 결정 |
|---|---|---|
| ① 하이브리드 | A안 배경 그림 + 3D 캐릭터 | 기각 — 카메라 자유도 제한 |
| ② 전부 3D | 지형·나무·바위·원경·캐릭터 모두 코드 | **사용자 선택** |

**대가:** 배경 품질이 원본 그림(A안)보다 떨어진다. 그 대신 카메라 자유도와 조명 일관성을 얻는다. 리포트에서 이 맞교환을 평가한다.

## 3. 룩 목표 *(내 판단)*

- 첨부 이미지 같은 **3D 애니메이션 풍**을 최대한 근사한다. 부드러운 PBR(MeshStandard/Physical)에 천은 sheen, 피부는 따뜻한 반사, 털은 셸(shell) 레이어로 처리한다.
- 툰 셰이딩(경계선이 딱 떨어지는 만화풍)은 쓰지 않는다. 참조 이미지가 부드러운 3D 렌더 룩이기 때문이다.
- 팔레트: 노을빛 태양 #ffb36b(낮고 왼쪽 뒤에서), 하늘 #9fb4d6 → #f3d2b8, 지면 흙 #c48a55, 소나무 껍질 #8a4a2b, 솔잎 #4f6b2e, 할머니 저고리 #a8574f, 치마 #7a4a57, 동정·끝동 #efe3cf, 호랑이 #e8862a, 줄무늬 #2a1a14, 배·볼털 #f3e6d0

## 4. 환경 (전부 코드)

| 요소 | 구현 |
|---|---|
| 지형 | 120×120 세그먼트 높이맵 평면. 시드 고정 노이즈 + 경사. 산길은 CatmullRom 곡선을 따라 깎고, 정점 색으로 흙길·풀·낙엽을 구분. 절차적 흙 텍스처(캔버스) |
| 소나무 | 줄기는 휜 곡선을 따라 TubeGeometry(붉은 껍질 노이즈 텍스처). 잎은 한국 소나무 특유의 수평 층(납작한 구 다발)을 InstancedMesh로 표현. 6~8그루, 시드별 변형 |
| 바위 | 노이즈로 변위한 Icosahedron + 윗면 이끼 정점색. InstancedMesh |
| 열매 덤불 | 잎(납작 타원체 인스턴스) + 빨간 구 열매. 전경 차폐에 사용 |
| 원경 | 산 능선 실루엣 메시 4~5겹(멀수록 푸르고 옅게), 운해 카드, 먼 능선 위 작은 정자(기둥 + 휜 지붕) |
| 하늘과 대기 | 그라데이션 하늘 돔, `scene.fog`, 먼지 파티클(A안 재사용), 빛줄기 카드 |
| 조명 | 낮은 노을 DirectionalLight + 그림자(PCFSoft, 2048 맵 1장, 캐릭터 주변으로 범위 제한), HemisphereLight(하늘/지면), 캐릭터용 림 라이트 |

## 5. 캐릭터 (전부 코드)

### 5.1 할머니
- **머리:** 약간 눌린 구. 눈은 흰자, 홍채, 동공, 하이라이트를 각각 구로 만든다. 눈꺼풀은 반구 스케일, 눈썹은 캡슐(각도로 겁먹은 표정), 코, 볼 홍조, 귀
- **입:** 어두운 타원 + 윗니 한 줄. 열림 파라미터로 비명
- **머리카락:** 회색. 머리통 덮개 + 쪽머리(토러스 + 구) + 비녀(갈색 원기둥)
- **옷:**
  - 저고리: LatheGeometry. 흰 동정·끝동, 고름 리본(TubeGeometry 리본 2가닥)
  - 치마: 넓게 퍼진 LatheGeometry. 주름은 정점 변위로 넣고, 걸음에 따라 펄럭임(2차 동작)
- **팔다리:** 팔은 소매 원기둥 + 손(구 + 손가락 4개 캡슐). 다리는 흰 버선 원기둥, 짚신은 타원체 + 짜임 노멀 텍스처
- **소품:** 바구니(LatheGeometry 짜임 텍스처 + 토러스 손잡이 + 천 보따리 구)
- **리그:** Object3D 계층(골반 → 척추 → 가슴 → 목 → 머리, 어깨 → 팔꿈치 → 손목, 고관절 → 무릎 → 발목). 각 부위는 강체로 관절에 붙인다.

### 5.2 호랑이
- **몸통:** 척추 곡선을 따라 매 프레임 단면 반지름을 바꾸는 튜브 메시(어깨는 굵고 허리는 잘록). 척추가 굽고 펴지는 갤럽 동작을 메시가 그대로 따른다. *(Three.js 동적 지오메트리 테스트)*
- **줄무늬와 배:** MeshPhysical `onBeforeCompile` 셰이더로 오브젝트 공간 좌표 + 노이즈 기반 줄무늬, 배쪽 흰 털 그라데이션
- **털:** 셸 텍스처링 8겹(같은 메시를 법선 방향으로 부풀린 반투명 층 + 노이즈 알파). 성능 예산을 넘으면 sheen만 쓰도록 단계적으로 낮춘다.
- **머리:** 두개골 구 + 주둥이 + **턱(경첩 회전, 대사·포효)** + 귀 + 노란 눈(동공 + 하이라이트) + 볼털(흰 셸) + 수염(가는 라인) + 찡그린 눈썹 털
- **다리:** 4개 × 3마디 + 큰 발(발바닥 패드 포함 — S5 클로즈업에서 보임)
- **꼬리:** 관절 체인을 따라 TubeGeometry, 끝은 흰색, 지연된 추종(follow-through)

### 5.3 애니메이션 (절차적)
- **보행:** 위상 φ 기반 보행 함수
  - 할머니: 2박자 달리기. 골반 상하·회전, 다리 스윙, 팔 흔들기(한 팔은 바구니를 감싸 쥠), 머리는 반 박자 늦게 따라옴
  - 호랑이: 갤럽. 척추 굴곡/신전, 앞다리 쌍과 뒷다리 쌍의 위상 차, 머리 안정화
- **발 고정:** 보폭 = 이동 속도 ÷ 걸음 빈도. 지지 구간의 발 월드 위치를 고정하고 지형 높이에 맞춘다(2관절 IK).
- **상태 블렌딩:** 상태(서기, 웅크림, 달리기, 뒤돌아보기, 예비 동작, 덮치기)마다 관절 각도 세트를 두고, 가중치를 0.15~0.3초에 걸쳐 바꾼다. 한 프레임 만의 교체는 금지.
- **표정 키:**
  - 할머니: 겁먹음 → S4에서 뒤돌아보며 비명(입 최대, 눈 크게, 머리 회전)
  - 호랑이: S3 능글맞은 대사 — 무음이지만 "어흥~ 떡 하나 주면… 안 잡아먹지이~" 음절 리듬으로 턱을 움직임. S5 포효(턱 최대, 눈썹 찡그림)
- **2차 동작:** 치마 펄럭임, 고름 리본, 쪽머리 흔들림, 꼬리, 귀, 볼털

## 6. 카메라 (자유 카메라 — B2의 핵심 증명)

| 샷 | 시간 | 연출 |
|---|---|---|
| S1 | 0.0–1.5 | 높은 곳에서 내려오는 크레인 다운. 산길과 운해·원경이 드러남 |
| S2 | 1.5–3.5 | 할머니 정면 앞 낮은 앵글, 카메라가 뒤로 물러나며 트래킹 |
| S3 | 3.5–6.0 | 열매 덤불 뒤 로우 앵글(전경 차폐). 호랑이가 웅크렸다 튀어나옴, 흔들림 |
| S4 | 6.0–8.0 | **측면에서 25~35° 오비트하는 투샷** (키아트 구도로 끝남). 할머니가 뒤돌아봄 |
| S5 | 8.0–10.0 | 호랑이가 카메라로 덮침. 화각 펀치인 → 9.3 정지·탈색·플래시 → 9.7 암전 |

- 후보정은 A안의 `post.js`(블룸, 그레이드, 비네트, 그레인, 정지·암전)를 재사용한다.

## 7. 구조와 테스트

```
b2-3d/                    새 HyperFrames 프로젝트 (A안과 같은 하네스)
  index.html, lib/ (three, gsap)
  src/ rng.js, post.js (A안에서 복사)
       terrain.js, flora.js, sky.js           환경
       grandma.js, tiger.js                   모델 + 리그 (Object3D 계층)
       anim/gait.js, anim/states.js, anim/face.js   순수 함수 (node 테스트)
       choreo.js                              샷별 경로·상태·표정 키
       camera.js, main.js
tools/test_b2_render.py   스냅샷 결정성·정지·암전 (A안 테스트 재사용)
tools/b2_anim.test.mjs    보행·블렌딩·발 고정 단위 테스트
```

### 자동 테스트
| 테스트 | 통과 조건 |
|---|---|
| 결정성 | 4s, 0s, 4s 스냅샷에서 두 4s 프레임이 픽셀 완전 일치 |
| 정지와 암전 | 9.4s = 9.6s, 9.95s 평균 밝기 < 5% |
| 발 미끄러짐 | 지지 구간에서 발 월드 위치 이동 < 보폭의 3% |
| 팝 없음 | 모든 관절의 프레임당 각도 변화 < 25° (S5 포효 제외 구간) |
| 성능 | 가장 무거운 프레임(S4 투샷) 렌더 시간 측정, 3초 미만 |

### 검수 지점
1. 캐릭터 턴어라운드 (정면 / 3·4 / 측면 / 후면 렌더) — 원본 캐릭터 시트와 나란히
2. 환경 와이드 + 샷별 스냅샷
3. 보행·표정 테스트 클립 (캐릭터 단독)
4. 720p 최종본 + A/B2 비교 영상 + 평가 리포트

## 8. 위험 요소와 대응

| 위험 | 대응 |
|---|---|
| 소프트웨어 WebGL 성능 (그림자 + 셸 털 + 인스턴스) | 단계적 품질 조절: 셸 8 → 4 → 0겹, 그림자 맵 2048 → 1024, 인스턴스 수 축소. 측정값을 리포트에 기록 |
| 도형 조합 캐릭터가 "장난감"처럼 보임 | 예상하는 결과다. 리포트에서 어디까지 근사했는지 기록하는 것이 목적 |
| 작업량이 큼 | 캐릭터 → 환경 → 애니메이션 → 카메라 순으로 검수 지점마다 확인 |
